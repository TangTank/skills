# SOP Guide — 问答式 SOP 编写引导

## 目的

通过分阶段的问答对话，引导不熟悉 SOP 的员工逐步梳理工作流程，最终生成一份标准化的 SOP 文档。

**与 sop-creator 的区别：** sop-creator 适合已有流程描述的用户直接生成；sop-guide 适合不熟悉 SOP 的用户，通过问答逐步梳理。

---

## 执行逻辑

**每次启动时，先执行阶段 0（公司信息确认），再进入阶段 1。**

### 阶段 0：公司信息确认

**目标：** 确保公司基础信息已记录，后续 SOP 可直接引用。

**检查 `sop-docs/背景介绍/company-context.md` 是否存在：**

#### 如果文件存在：

1. 读取文件内容
2. 用 AskUserQuestion 展示公司信息摘要，让用户确认：
   - "以下是你之前保存的公司信息，是否正确？"
   - 选项：正确，继续 / 需要更新
3. 如果用户选择"正确" → 进入阶段 1
4. 如果用户选择"需要更新" → 进入信息收集流程（见下方）

#### 如果文件不存在：
通过 AskUserQuestion 收集公司信息（参考 `reference/company-context-template.md`）：

1. 公司名称
2. 所属行业/主营业务
3. 公司有哪些部门？
4. 使用哪些业务系统/软件？（ERP、CRM、OA等）
5. 日常用什么沟通工具？（企业微信、钉钉、邮件等）
6. 文件一般存放在哪里？（共享盘、云文档等）

收集完毕后，将信息保存到 `sop-docs/背景介绍/company-context.md`，然后进入阶段 1。

### 进入阶段 1

**检查 $ARGUMENTS：**

#### 如果 $ARGUMENTS 为空：
使用 AskUserQuestion 询问：
"你好！我来帮你梳理工作流程并生成 SOP 文档。请告诉我你要梳理哪个部门、哪个岗位的什么流程？"

然后等待用户回复，进入阶段 1。

#### 如果 $ARGUMENTS 包含内容：
从 $ARGUMENTS 中提取部门、岗位、流程信息，直接进入阶段 1（跳过打招呼）。

## 批量模式

当用户需要为同一部门梳理多个流程时，支持批量模式：

1. **流程盘点阶段：** 先询问用户该部门还有哪些流程需要梳理，列出完整清单
2. **优先级排序：** 与用户确认梳理顺序
3. **逐个梳理：** 按顺序逐个完成 SOP
4. **进度追踪：** 每完成一个 SOP，更新进度并询问是否继续

**触发条件：** 用户提到"梳理多个流程"、"逐步完成"、"先列计划"等

---

## 引用现有 SOP

当用户提到参考已有 SOP 或创建平台变体时：

1. **查找相关 SOP：** 使用 Glob 搜索 `sop-docs/**/*SOP.md`
2. **读取参考文档：** 读取用户指定或最相关的 SOP
3. **提取共性部分：** 识别可复用的步骤和结构
4. **标注差异点：** 明确新 SOP 与参考 SOP 的区别
5. **生成新文档：** 基于参考 SOP 调整生成新 SOP

**平台变体命名规范：**
- 天猫：`天猫-[流程名称]SOP.md`
- 京东：`京东自营-[流程名称]SOP.md`
- 通用：`[流程名称]SOP.md`

---

## 复杂流程处理

当流程涉及多个部门协作或问题较复杂时，集成深度追问能力：

1. **问题拆解：** 将复杂问题拆解为多个子问题
2. **链路梳理：** 明确信息在部门间的流转路径
3. **痛点识别：** 找出当前流程的核心痛点
4. **方案设计：** 基于痛点设计优化方案
5. **技术需求：** 如需系统支持，明确技术实现需求

**触发信号：** 用户提到"优化"、"改进"、"跨部门"、"系统对接"等

---

## 流程导航集成

创建 SOP 完成后，自动更新流程导航文档：

1. **检查导航文件：** 确认 `sop-docs/流程导航.md` 是否存在
2. **添加部门分类：** 如部门不存在，新增部门分类
3. **添加流程条目：** 在对应部门下添加新 SOP 链接
4. **更新业务场景：** 如有相关业务场景，更新场景流程图
5. **更新全部清单：** 在全部流程清单中添加新条目

### 阶段 1：基础信息收集

**目标：** 确定 SOP 的基本框架

**提问内容（根据已有信息跳过已知项）：**
1. 部门名称
2. 岗位名称
3. 要梳理的工作流程名称
4. 这个流程目前有没有口头约定或书面记录？

**阶段结束：** 总结收集到的基础信息，确认后进入阶段 2。

---

### 阶段 2：流程概述

**目标：** 理解流程的全貌

**提问内容：**
1. 这个流程是做什么的？目的是什么？
2. 什么情况下会触发这个流程？（收到某个通知？客户提出需求？定期执行？）
3. 流程执行完成后，应该达到什么结果？
4. 执行这个流程需要用到哪些系统、工具、文件？

**追问策略：**
- 如果用户回答模糊（比如"就是正常做"），追问具体例子
- 如果用户提到多个触发条件，逐一确认

**阶段结束：** 总结流程概述，确认后进入阶段 3。

---

### 阶段 3：准入检查（必填）

**目标：** 明确执行流程前必须满足的前置条件

**提问内容：**
1. 在开始执行这个流程之前，需要确认哪些东西已经准备好了？（比如权限、材料、系统状态、数据等）
2. 需要谁的审批或确认才能开始？
3. 有没有什么是"不满足就不能开始"的硬性前提？

**追问策略：**
- 如果用户说"没什么特别的"，引导思考：
  - "需不需要特定的账号或权限？"
  - "需不需要收到什么文件或通知才能开始？"
  - "需不需要某个系统处于特定状态？"
- 至少收集 1 项准入条件

**阶段结束：** 总结准入检查清单，确认后进入阶段 4。

---

### 阶段 4：流程步骤

**目标：** 逐步梳理流程的每个关键步骤

**提问内容（循环，直到用户确认流程梳理完毕）：**
1. 第一步做什么？具体怎么操作？
2. 这一步做完后，应该看到什么结果？
3. 如果这一步出错了，怎么办？
4. 有没有需要特别注意的地方？（风险点、易错点）

**追问策略：**
- 每个步骤追问操作细节："具体在哪里操作？用什么工具？填什么内容？"
- 每个步骤追问异常处理："如果系统报错了怎么办？如果数据不对怎么办？"
- 如果用户跳步，提醒："在你刚才说的 X 和 Y 之间，还有没有中间步骤？"
- 当用户说"就这些了"，回顾步骤列表确认完整性

**阶段结束：** 列出完整步骤清单，逐一确认后进入阶段 5。

---

### 阶段 5：交付标准（必填）

**目标：** 明确流程完成的判断标准和交付物

**提问内容：**
1. 怎么判断这个流程做完了？（结束标志是什么？）
2. 完成后需要交付什么成果物？（文件、数据、报告、通知等）
3. 交付物需要满足什么质量标准？（谁来检查？检查什么？）
4. 完成后需要通知谁？走什么确认流程？

**追问策略：**
- 如果用户说"做完就行了"，引导思考：
  - "有没有一个清单可以打勾确认都做完了？"
  - "需不需要谁签字或确认？"
  - "做完后谁会检查你的工作？"
- 至少收集 1 项交付标准

**阶段结束：** 总结交付标准，确认后进入 SOP 生成。

### 写作规范
- 语言：中文
- 句子简短，每句一个动作
- 步骤以动词开头（打开、填写、检查、提交、通知）
- 每个步骤包含预期结果
- 关键步骤包含异常处理
- 风险步骤包含注意事项

### 强制包含
- **准入检查**（第五章）：至少 1 项，使用表格格式
- **流程图**（第六章）：必须包含 ASCII 文本流程图，展示主要步骤和分支
- **交付标准**（第八章）：至少 1 项，使用表格格式

### 文档编号规范
- 格式：`SOP-[部门缩写]-[序号]`
- 示例：SOP-EC-001（电商运营部第1个 SOP）
- 部门缩写：EC（电商运营）、PUR（采购）、SALES（销售）、FIN（财务）、CS（客服）

### 文档编号规范

## 质量检查清单

生成 SOP 前自检，**任何一项不通过则修改后再呈现：**

### 内容完整性
- [ ] 准入检查部分不为空（至少 1 项）
- [ ] 交付标准部分不为空（至少 1 项）
- [ ] 包含流程图（ASCII 格式）
- [ ] 每个步骤有预期结果
- [ ] 关键步骤有异常处理
- [ ] 角色职责明确

### 信息准确性
- [ ] 所有信息来自用户回答，未编造
- [ ] 待补充项已用 `[待补充]` 标记
- [ ] 步骤顺序与用户描述一致

### 格式规范
- [ ] 文档信息使用表格格式
- [ ] 准入检查使用表格格式
- [ ] 交付标准使用表格格式
- [ ] 流程图使用 ASCII 文本格式
- [ ] 中文表述清晰
- [ ] 文档编号符合规范
- [ ] 文件名符合命名规范

## 默认值

- **语言：** 中文
- **版本：** 1.0
- **日期：** 当前日期
- **阅读水平：** 普通员工可理解（避免专业术语，必要时解释）
- **流程类型：** 可重复执行的业务流程（非一次性任务）
- **文件保存路径：** `sop-docs/[部门名称]/[流程名称]SOP.md`
