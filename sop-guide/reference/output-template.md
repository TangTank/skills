# SOP 输出模板

生成 SOP 时使用以下格式。`[方括号内容]` 为占位符，用用户提供的信息替换。
标注 `[待补充]` 的项目表示用户未提供相关信息，需后续完善。
标注 `[可选]` 的章节可根据流程复杂度决定是否包含。

---

```markdown
# [流程名称] SOP

## 一、文档信息

| 项目 | 内容 |
|------|------|
| 文档名称 | [流程名称] |
| 文档编号 | SOP-[部门缩写]-[序号] |
| 版本号 | V1.0 |
| 生效日期 | [当前日期] |
| 编制部门 | [部门名称] |
| 适用岗位 | [岗位名称] |
| 协作部门 | [协作部门] |
| 审批人 | [待补充] |

---

## 二、目的与范围

### 2.1 目的

[一句话说明这个流程做什么、为什么做。例如：本流程用于规范 XX 岗位在 XX 场景下的 XX 操作，确保 XX 结果。]

### 2.2 适用范围

- **适用部门：** [部门名称]
- **适用岗位：** [岗位名称]
- **触发条件：** [什么情况下启动本流程]

### 2.3 业务背景 [可选]

[说明该流程所处的业务背景，帮助新人理解"为什么需要这个流程"。例如：公司主营商品采用 OEM 模式，由供应商按订单直接发货给客户……]

---

## 三、相关定义与缩略语 [可选]

> 流程中涉及专业术语或缩略语时使用。如无术语可省略本章。

| 术语 | 定义 |
|------|------|
| [术语1] | [定义] |
| [术语2] | [定义] |

---

## 四、角色与职责

|------|------|
| [执行人岗位] | 负责执行本流程的全部步骤 |
| [审核人岗位] | 负责 [具体审核内容] |
| [协作岗位] | 负责 [具体协作内容] |
| [知会人岗位] | 需知悉流程执行结果 |

| 2 | [检查项2] | [具体标准] | [怎么解决] |
| 3 | [检查项3] | [具体标准] | [怎么解决] |

## 六、流程图

> **每个 SOP 必须包含流程图，使用文本流程图（ASCII 格式）。**

```
┌─────────────┐
│  [步骤1]     │ ← [责任人/触发条件]
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  [步骤2]     │ ← [责任人]
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  [步骤3]     │ ← [责任人]
└──────┬──────┘
       │
       ├──────────────┐
       ▼              ▼
┌─────────────┐ ┌─────────────┐
│ [正常结果]   │ │ [异常结果]   │
└─────────────┘ └─────────────┘
```

**流程图绘制规则：**
- 每个方框代表一个步骤，用简短标题
- 箭头表示流程方向
- 分支用 `├──` 表示，标注分支条件
- 在方框右侧用 `←` 标注责任人或触发条件
- 如有循环（如审核不通过退回），用虚线箭头标注
```

## 填写说明

### 一、文档信息
- 使用表格格式，信息一目了然
- 文档编号格式：`SOP-[部门缩写]-[序号]`
- 部门缩写：EC（电商运营）、PUR（采购）、SALES（销售）、FIN（财务）、CS（客服）

### 二、目的与范围
- 目的一句话说清楚：谁、在什么情况下、做什么、达到什么结果
- 触发条件要具体，比如"收到客户退款申请邮件后"而不是"需要的时候"
- 业务背景帮助新人理解流程存在的原因，可选但推荐

### 三、相关定义与缩略语
- 只在流程涉及专业术语时使用
- 如果没有术语，整个章节省略

### 四、角色与职责
- 只列与本流程相关的角色
- 职责要具体，不要写"配合工作"

### 五、准入检查
- 使用表格格式，每项包含检查标准和未满足时的处理方式
- 每项必须是可检查的（能回答"是/否"）
- 至少 1 项

### 六、流程图
- **每个 SOP 必须包含流程图**
- 使用文本流程图（ASCII 格式），不依赖外部工具
- 展示流程的主要步骤和分支
- 标注每个步骤的责任人
- 如有异常分支，明确标注

### 七、详细步骤
- 每个步骤以动词开头
- 一句话一个动作，不要把多个动作合并
- 每个步骤标注责任人
- 关键步骤必须有预期结果
- 涉及数据、金额、审批的步骤必须有异常处理
- 操作路径帮助用户快速找到系统入口

### 八、交付标准
- 使用表格格式，每项包含质量标准和检查方式
- 每项必须是可衡量的（能回答"是否达标"）
- 至少 1 项

### 九、异常处理汇总
- 使用表格格式，包含责任人和上报对象
- 只列常见异常，不需要穷举
- 每个异常必须有明确的处理方式

### 十、常见问题
- 优先收录新人容易遇到的问题
- 解决方法要具体可操作
- 可选章节，根据流程复杂度决定

### 十一、相关文件与工具
- 使用表格格式，列出存放位置和用途
- 列出执行流程需要的所有外部资源

### 十二、流程优化计划
- 可选章节
- 记录已知的改进方向，便于后续迭代

### 十三、修订记录
- 每次修改 SOP 都要记录
- 记录修改人和修改内容
