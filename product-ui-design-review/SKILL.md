# 产品界面设计与交互评审

从用户的任务出发，确定每一步要看什么、判断什么、做什么，以及怎样知道已经完成。落实指定批注、修复已确认问题或评审未提交代码时，使用 `review-and-improve-changes`。

以实际页面、业务规则和项目规范为依据。参考页跨端时，明确哪些信息分组、组件和视觉层级可以沿用，按目标端的空间和输入方式安排布局与交互。跨页统一时，先核对同类页面的权限和数据差异，再对齐标题、留白、状态和操作。优先复用已有组件和设计 token，图标默认用中性单色，按用户要求加色。

## 做设计

1. 写清角色、数据范围、入口和完成信号。从入口走到结果，再补会影响任务的返回、失效、无权限或失败分支。局部改动从受影响的步骤开始。
2. 安排首屏、展开区和详情，标清入口、主次动作与决策依据的位置。说明首次进入的默认值及来源，以及返回、切换业务范围、选项失效或撤权时如何处理已有选择。批量操作要写明「全选」覆盖的范围和生效条件。
3. 说明关键状态出现在哪里、用户接下来能做什么。涉及金额、对象或范围时，写清数据来源、确认时的核对项和恢复路径。部分成功时逐项呈现结果，并明确哪些项可以重试。
4. 交付任务路径、页面结构、主次动作、关键状态和验收场景。按「起始状态 → 操作或外部变化 → 可见结果和可用动作」写关键场景，涉及提交时补充实际生效的对象或范围。需要草图或原型时画出主路径和会改变决策的状态。用户要求实现时按项目流程落实。

## 做评审

1. 确定被评页面、角色、数据和目标端。能运行时沿实际入口操作，记录环境和证据。用截图或原型评审时，结论限于素材对应的状态和平台。对已变化的状态、未操作的步骤和其他端，写出待验证条件。
2. 用下表检查关键步骤，优先核对任务中断、错选错提交和状态误导。将批注对应到控件与状态，同类问题合并时保留受影响的入口。
3. 每条发现写清位置、触发条件、观察结果、任务影响、具体改法和验收条件。标明观察或推断的依据。只讨论或评审时交付发现和改进建议，验收场景供后续复测。

## 设计与评审检查表

| 维度 | 设计时要决定 | 评审时要验证 |
| --- | --- | --- |
| 主次动作 | 明确当前步骤最重要的动作，给次要、返回和高风险动作合适的位置与视觉权重。按钮写出操作结果。 | 用户能辨认下一步，也能找到退出或取消。次要动作和危险动作不会被误当成主动作。 |
| 信息分组 | 将需要一起理解、比较或操作的字段、状态和动作放在同一区块。用任务语义命名。 | 组名和内容相符。用户能在一个区块读完同一个业务对象的关键信息。 |
| 任务完成路径 | 从实际入口串到明确的完成结果。为权限变化、中断或失败安排可继续的路径。 | 用一个具体角色从入口做到结果。检查完成提示、后续去向和中断后能否继续。 |
| 功能可发现性 | 在用户预期的位置放入口，使用熟悉的词。折叠区标明可展开的内容。 | 从首次使用视角找常用功能。图标、隐藏菜单或长按入口有清楚的提示或可见的等效入口。 |
| 状态可见性 | 在受影响的位置给出反馈和后续动作。区分加载、刷新、空、未知、失败、无权限、部分成功和完成。 | 触发相关状态，检查对象、结果和下一步是否可见。 |
| 错误预防 | 限制无效组合，在相关字段解释错误。高影响操作在确认前展示对象、范围和后果，条件变化时重新核对。 | 尝试错选、漏填、重复提交或在确认前改变数据。检查拦截位置、提示和重新操作的路径。 |
| 默认值 | 明确初始值的业务依据，让用户看得见、改得动。为旧选择失效或无可选项定义回退。 | 核对首次进入、返回和范围变化时的取值。同一范围内有效的手动选择应能恢复。 |
| 渐进披露 | 将当前任务所需信息、限制和高风险后果放在决策前。低频详情用展开、下钻或按条件出现的字段承载。 | 从首屏找到展开或详情入口。展开后能顺畅返回，上一步的选择和上下文仍可用。 |
| 决策距离 | 把判断依据放在动作附近，例如在「下一步」旁展示已选数量、金额和统计范围。 | 到达动作时能直接核对对象、范围、数量或后果，查看依据时不会丢失当前选择。 |
| 操作路径 | 检查完成某一步需要的点击、滚动、翻页和返回。保留有业务价值的核对步骤。 | 从真实入口逐步操作，找出重复录入、来回切页、无意义的确认和返回后重做。 |
| 信息密度 | 按任务和视口决定一屏的信息量。对齐可比较的字段，把低频信息留在按需区域。 | 用长文案、多条记录和实际目标视口检查可扫读性。关键字段易比较，操作区可达。 |
| 认知负担 | 统一术语、日期和金额口径。把当前筛选、选择、合计与下一步所需信息显示出来。 | 检查用户是否需要记住上一屏的数字、猜测词义、心算合计或重复确认同一件事。 |
| 视觉权重 | 用位置、字号、字重、对比度和间距体现重点。状态同时用文字或符号表达。 | 看首屏最醒目的元素是否对应当前重点。检查主题下的对比度、焦点和触控可达性。 |
| 信息层级 | 按当前判断所需顺序排列标题、摘要、正文、辅助信息和详情入口。 | 快速扫过页面能说出当前对象、主要结论和下一步。阅读顺序与操作顺序相容。 |

## 已有页面示例

- **TopPartner · 供应商详情。** 先满足「看这家供应商待收和已结算多少、去哪里查明细」。把收款概览放在企业资料下、经营概览上，订单和账单报表提供按权限展示的直达入口。验收时对照接口日期和金额，分别看真实零值、只有数量查看权限和请求失败的表现。适用于信息分组、信息层级、功能可发现性和状态可见性。
- **TopPartner · 对账选单。** 将已选笔数和金额放在「下一步」旁可缩短决策距离。验收场景是两页各选一笔，在确认页期间让其中一笔失效，返回后只保留有效订单，选单与合计同步更新。全部失效时「下一步」不可用，用户可以重新选单。
- **智慧厨房 · 食安首页。** 首次进入默认选中首个获准餐厅，返回时保留有效的手动选择。右侧目录跳到对应区块，并随页面滚动更新当前位置。验收覆盖无获准餐厅、权限变化、卡片重排和目录定位，按桌面 Web 的实际使用路径走查。适用于默认值、操作路径和状态可见性。
- **智慧厨房 · 工艺版本表单。** 方案名称放首行。选择「设备制作」时，展示并要求填写设备型号和固定物模型版本。用漏填提交验证字段提示与拦截，再切回「人工制作」检查设备字段的错误提示是否清除。适用于渐进披露和错误预防。
- **HeidiEnglish · 我的短文。** 参考「我的」页的绿色页头，把返回和角色选择纳入同一个页头区域。角色选择是视觉重点，保留可识别的返回入口。用同一视口对照布局，检查点击与 Enter／Space 能进入选择，以及返回后能继续查看短文。适用于参考页改版、主次动作和视觉权重。
